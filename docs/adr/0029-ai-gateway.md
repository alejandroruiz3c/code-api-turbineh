# ADR-0029 · TurbineH AI gateway: client AI apps use TurbineH's keys

- Status: accepted (owner decision, 2026-10-12)
- Date: 2026-10-12
- Extends: ADR-0028 (orchestrator #001 and AI Safety Pack).

## Context

The owner decided that AI apps generated by TurbineH must not ask clients for JEV/TypeSafe or model-provider keys:
they use TurbineH's, and TurbineH charges for usage later. Shipping our keys inside client apps (their repository,
their Vercel project) would let anyone with access copy and use them without limits.

## Decision

- **Gateway** in the web app: `POST /v1/ai/v1/chat/completions`, `/v1/ai/v1/embeddings` and `/v1/ai/v1/systemone`
  (the paths the orchestrator and the official `@typesafe-ai/sdk` call). Auth with a per-app token (`tbh_ai_…`, stored
  hashed, revocable). Requests are validated (model allow-list of documented open models, message/input sizes, output
  token cap, timeout) and forwarded with TurbineH's keys, which never leave our servers. Provider errors are never
  echoed; prompts, outputs and keys are never logged.
- **Limits and usage:** per-app requests per minute and daily token quota (`AI_GATEWAY_RPM`, `AI_GATEWAY_DAILY_TOKENS`);
  usage per app and day (calls, tokens in/out, model, endpoint) for billing and for the client usage metric to come.
  Cost stays internal (ops panel).
- **Client apps:** the orchestrator calls the gateway (`TURBINEH_AI_URL`, `TURBINEH_AI_TOKEN`); no AI keys to configure.
  "Deploy for me" creates the token and sets it; self-hosting clients get it from the build page ("Get AI access
  token", shown once). The AI Safety Pack still runs inside the app; the gateway adds a server-side boundary.
- **Revocation:** abuse is stopped by revoking one app's token, without touching TurbineH's keys.

## Environment (Vercel, web)

`AI_GATEWAY_UPSTREAM_URL`, `AI_GATEWAY_UPSTREAM_KEY` (model provider), `AI_GATEWAY_TYPESAFE_KEY` (JEV),
`AI_GATEWAY_DAILY_TOKENS`, `AI_GATEWAY_RPM` — set by `infra/staging/web.ts env`.
